1. 操作ボタン（ktn-op-btn）— モーダル・大型CTA
主な変更点： --primary を var(--page-accent) から 固定ブルー #1a4a88 に変更。 決定ボタンの色をロール・ページを問わず統一し、ユーザーが「青＝実行する」と学習できるようにする。 ページアクセントカラー（クリエイター色・ギャラリー色）はナビ・ブランドのみに使用。
--caution（会場売約済など）は #8b5e3c（ギャラリーコッパー）。--primary が固定ブルーのため P4 Gallery 管理ページでも衝突しない。

4. ナビゲーションボタン（ktn-action-btn）— ページ遷移・コンソール内リンク
v3 原則：塗りつぶし（solid）＝「その場で実行される操作」専用（ktn-op-btn 系のみ）。 ページ遷移ボタンは要対応状態でもアウトライン＋赤ドットに留め、hover でのみ塗る。 solid 赤は「押すと何かが確定・破壊される」サインとして ktn-op-btn--danger に予約。 これによりナビと操作が形で見分けられ、要対応ナビが操作ボタンより目立ちすぎる問題を解消。
記号ルール（v3.1 確定）：
・末尾「 →」＝ページ遷移するボタン（ktn-action-btn）に必ず付ける。テキスト「 →」で統一し SVG 矢印は使わない。
・先頭「●」＝「遷移先に要対応の取引がある」通知サイン。--alert / --alert-dark / :has() 要対応状態で CSS（::before）が自動付与。HTML に手で書かない。
・要対応ナビの完全形＝「● ラベル →」／通常ナビ＝「ラベル →」。
・矢印なし＝遷移しない（その場で実行 or モーダルを開く）。カラー帯内の操作トリガー（myコレクションへ等）は --ghost を共用するが矢印を付けず機能アイコンを付ける。
default（通常ナビ） 取引デスクへ → 出品管理 → LIAISON+ → — グレー枠 / 透明背景
--alert（要対応ナビ） 発送処理へ → 在庫確認へ → — 赤アウトライン＋ドット＋矢印（● ラベル →）/ hover で塗り v3 変更
Dark background context（p2-5-1 LIAISON+ダーク版など）
--alert-dark 発送処理へ → 在庫確認へ → — 明オレンジのアウトライン＋ドット＋矢印 / hover で塗り v3 変更
--dark（ダーク上通常ナビ） 詳細を見る → 作品一覧へ → — 半透明白枠（手動スタイル廃止・クラス化） v3 新設

--ghost：カラー帯内でのみ使用。白背景では使わない。

5. 取引ステータスバッジ — ボタンと形で区別する
定義（v3.1 確定）：ステータス＝「先頭ドット＋淡色塗り・枠線なし・矢印なし」。クリック不可・hover 変化なし。
ボタンは必ず「枠線＋白/透明背景」を持ち、遷移するものは末尾「 →」を持つ。 この形の差で「押せるもの／状態を示すだけのもの」を見分ける。 本番実装は .p515-status__badge（共通ベース・取引4ページ共用）＋状態別カラークラス。
取引状態（S1〜F2） 購入確定待ち 支払待ち 発送待ち 受取確認待ち 完了確認待ち 取引完了 キャンセル済
種類 形 記号 例
実行ボタン（その場で確定） solid 塗り なし
破壊操作トリガー（モーダルが開く） 赤枠・白背景 なし
通常ナビ（ページ遷移） グレー枠・白背景 末尾 → 取引デスクへ →
要対応ナビ（遷移先に要対応あり） 赤枠・白背景 先頭●＋末尾 → 発送処理へ →
ステータスバッジ（押せない） 淡色塗り・枠なし 先頭●（矢印なし・hoverなし） 購入確定待ち
破壊操作トリガーと要対応ナビはどちらも赤枠だが、ナビは「●＋→」を持ち、トリガーは記号を持たない。 また、ステータスバッジと要対応ナビはどちらも●を持つが、バッジは塗り・枠なし、ボタンは枠＋白背景。 p5-14 のストリップ行（状態行）は「ストリップのドット＋ラベル」＝ステータス表示、「枠付き＋→」＝ナビ、と同じ規則に従う。

横並び時の関係ルール（v3 確定）：
  • 1行（1ボタン列）に色付きボタンは1つまで。主アクション以外はアウトラインに落とす
  • モーダル・送信バーでは主アクションを右端、キャンセル系を左に置く
  • 同じ性質の操作は同じ見た目：実行系＝solid（op-btn--primary/--danger/--caution）／遷移系＝アウトライン＋末尾 →（action-btn）／破壊系ソフトトリガー＝赤枠・記号なし（--danger-outline）
  • サイズは置き場所で決める：モーダル＝標準・ページ大型CTA＝--lg・カード/コンソール内＝--sm（action-btn は1サイズのみ）
  • 並列の破壊操作（会場売約済＋出品取消など）は両方ともアウトラインにし、確認モーダル側の実行ボタンで solid を使う
