# 管理者の仕事と権限（2026-10-29・表は確定）

LIAISON+ の導入で管理の仕事が増えるのに備えて、管理者を3種類に分ける。**管理の仕事はすべて P90 系のページから行う**（ユーザーの方針・2026-10-27）。この表は、今ある管理の仕事を全部（P90 系のページ・各ページのヘッダーの「管理者」メニュー・編集画面の中の管理者だけの欄）並べ、ユーザーの決定を入れたもの。表は 2026-10-29 にすべて決まった。画面の直しは下の「画面の直し」。

## 3種類の権限

| 記号 | 名前（仮） | できること |
|---|---|---|
| **E** | 編集・問合せ対応 | 表示系のページの確認、展覧会の確認、各ページからの問合せ対応（LIAISON+ を除く） |
| **L** | LIAISON+ 対応 | E のすべて＋LIAISON+ の取引の確認、LIAISON+ の問合せ対応 |
| **A** | admin | すべて（今の管理者と同じ） |

入れ子（E ⊂ L ⊂ A）。印：**○**＝使える／**見る**＝見るだけ（操作のボタンは出さない）／**×**＝出さない・開けない。「決定」の列：**済**＝ユーザーが決めた（2026-10-29）。

## 公開のページの「管理者」メニュー（案2・2026-10-29 ユーザー決定）

- **公開のページ（P90 系以外）のヘッダーの「管理者」メニューは admin だけに出す**。「編集・問合せ」「LIAISON+ 対応」の管理者には出さない（オーナーメニューも出さない）。その人たちの仕事の入口は、すべて P90 系。
- **P90 系から開く編集画面（P2-11・P3-11・P4-11・P6-11・P7-11・P8-11）の中の管理者の欄は、この表のとおり**（管理者コメント・P2-11 の確認と管理者管理の欄は E 以上）。例外＝P3-11・P4-11・P5-11 のキャンペーンの枠は admin だけ（L は P90-20 で見る）。
- 公開のページの管理者の操作（ヘッダーのメニューの削除・強制削除・強制退会・なりすましログイン、作品のページのコメントの削除）は、P90 系と同じ手順を通す（理由のモーダル＋DL-01A／MO-03A）。
- **なぜ**：ページのメニューまで項目ごとに3種類で出し分けると、全ページの全項目に権限を付けることになり、作る量・確かめる量・将来の保守が大きくなる（ユーザー）。「管理の仕事はすべて P90 系から」の方針にもそろう。将来 E・L も公開のページから操作したくなったら、そのときに項目へ権限を付けて広げる（操作は P90 系と同じ共通の処理に寄せてあるので、あとから広げられる）。
- 実装：common.js `KTN.headerRole(page, role)`（admin 以外の管理者は、公開のページでは管理者の操作を持たない役割として描く）・`KTN.isFullAdmin()`・`syncAdminNote`（キャンペーンの枠だけ admin）。デモバーのロールの「管理者」は「管理者-A」「管理者-L」「管理者-E」の3つのボタンに分けて並べる（ロールに「管理者」があるページすべて・公開のページでは読み直さずに描き直す・P90 系は読み直す）。サイドバー・下のナビの管理者のアイコンも、文字（A／L／E）と色で見分け、名前を「管理者-A」などにする（common.js `ktnRoleDef`）。

## 削除の決まり（2026-10-29 ユーザー決定）

展覧会・クリエイター・ギャラリー・作品・記事・レビューの削除は、どれも同じ手順にする。

- 削除するときは、**モーダルで削除の理由を書く**（必須）。重複の整理などで、確認の作業の中で消すことがあるため。
- 削除すると、**理由を書いた自動のメールが管理者あてに届く**（新しいメール・下の「足すメール」）。だれが・何を・なぜ消したかが残る。

## コメントの決まり（#25・2026-10-29 ユーザー決定）

- **LIAISON+ に出品中の作品のコメントは分けない**。コメントは公開の感想で、作品の購入・取引についての質問は非公開のお問合わせ（P6-13）で受ける決まり。見る基準（掲載内容に関する対応方針）も同じなので、「編集・問合せ」の管理者がまとめて見られる。
- そのうえで、コメント管理の一覧に**「LIAISON+ 出品中」の印**を付ける（絞り込みは 2026-10-31 にやめた＝ユーザー判断。P90-3 は最新10件と、作品・投稿者の NID・UID で探す形にしたため）。購入の相談（値下げの交渉・連絡先の交換など）が公開のコメントに書かれたときに、LIAISON+ 対応の管理者が気づいて、お問合わせへ案内したり非公開にしたりできる。
- 分けると、LIAISON+ 対応の管理者が普通の感想の確認まで受け持つことになり、手間が増えるだけになる。

## 返金と強制キャンセルの分け方（#37・#47・2026-10-29 ユーザー決定）

- **返金のリクエストを受けて確かめ、返金の手続きを進めるのは L 以上**（#47）。
- **取引を強制的にキャンセルするのは A だけ**（#37）。

## 実装のときに守ること（後工程）

- 画面で隠すだけでなく、サーバー側（API）でも権限ごとに止める。
- Drupal は「ロール＋権限」で作る。1人に複数のロールを付けられるので、入れ子にせず「E の権限の集まり」「LIAISON+ の権限の集まり」を足し合わせてもよい。
- 管理者の操作は記録する（#55）。削除は理由とあわせて必ず記録する。
- プロトタイプは「admin かどうか」で出し分けている（common.js 33か所・pages.js 18か所・HTML 109ページ）。分けるときは「この操作ができるか」で判定する形（例：`KTN.can('txn.view')`）に置き換え、デモバーに管理者の種類の切り替えを足す。
