# 自動送出メール文面集（個展なび）

> 2026-10-08 に P90-9 の「全メール一覧」（`kotennavi-pages.js` の `AUTO_TRIGGERS`）と突き合わせ済み：自動送信 53 件の ID はすべて発火点の棚卸しの表にあり、文面の節がある 50 件の件名は完全に一致。表にだけある M-02・M-04・M-06〜M-10・E-02 は事務局が手で送るメール（P90-2・P90-11 等のテンプレート＝`docs/mail-template-system.md`）。M-03A は M-01A と本文を共有、N-01・A-04 は「ユーザーが選べるメール」の節に文面がある。

サイトからユーザーへ自動送出するメール（申込受付・機能付与完了・取引各フェーズ通知 等）の**文面の単一ソース**。UI と同じく「捕捉は決定時、構造化は後」の原則で、確定した発火点から順に文面を起こして追記していく（完成後にまとめて作らない）。

## 位置づけ・進め方

- **本番実装は Drupal（バックエンド）が送出**する。本ファイルは Drupal 実装フェーズへ渡す**文面と発火条件の仕様**であり、HTML/CSS のメールテンプレート実装そのものではない。
- **まずプレーンテキスト文面を確定する**。装飾HTMLメール化は Drupal フェーズで別途行う（プレーンが常に fallback として要るため先に固める）。
- 文面中の可変値は **`{{token}}` プレースホルダー**で書く（下記「トークン規約」）。
- 1通ごとに「発火点／受信者／トリガー／件名／本文」をワンセットで書く。**発火点の棚卸し（下表）が index、各文面が本体**。
- サイト内の状態名・期限呼称・ページ呼称は **CLAUDE.md / docs/transaction-states.md が canonical**。メール文面もそれに従い、独自の言い換えをしない（例：状態名「購入確定待ち」、期限呼称「確定期限」）。

**① リマインダーの細則**
- 「今日から開催／もうすぐ開催／もうすぐ終了」の判定は、サイトの開催ステータス（`.sb-*`：開催中・もうすぐ開始・もうすぐ終了）と同じ基準を使う（メール独自の日数を持たない）。
- **同じ展覧会が複数日にわたって届いてよい**（「もうすぐ終了」の期間中は毎日載る）。ユーザー判断：旧 daily mail が嫌われたのは、ウォッチも興味あり！もしていない＝アクションをしていないユーザーに毎日届いたため。自分でウォッチ・興味あり！した展覧会のリマインドは、繰り返し届いても役に立つ。
- ウォッチ中の展覧会と「興味あり！」の展覧会が重なる場合、同じメールには**1回だけ**載せる。
- 旧 daily mail にあった「開催中の展覧会すべて」と「ピックアップ展覧会（ウォッチ0件の人向け）」は廃止。ウォッチ0件の人への案内は P5（myページ）のゼロ状態の表示が担う。

**④ にコメント（A-05）を含める理由**：コメントは急ぎの対応が要らないので、止められるメールにする（ユーザー判断）。設定の数を増やさないよう、同じクリエイター・ギャラリー向けの④に含め、名前を「ウォッチ・チェックイン・コメントのお知らせ」に広げた。サイト内ではお知らせ（あなた宛 NT-06）にも出る（docs/notifications.md）。

**② ウォッチ新着の細則**
- **作品は対象外**：LIAISON／LIAISON+ では作品を頻繁に追加・取り下げするため、通知すると通数が読めず、取り下げた作品の通知も届いてしまう。
- **記事は展覧会の会期に関係なく必ず通知する**（会期後のお礼の記事など、アーカイブの展覧会に記事が載ることがあるため）。
- 会期が終わった展覧会を後から登録した場合（アーカイブ目的）、その**展覧会自体の公開通知は送らない**。

**③ 個展なびからのおすすめの細則**
- 送るかどうかは**事務局が1件ずつ選ぶ**（P61-11「登録ユーザーにメールでも送る」のチェック）。お知らせを公開するたびに自動では送らない（通数が増えすぎないように）。
- 配信先は P61-11 の「対象」（5種類・2026-09-29）で決める。ゲストにはメールを送れないため、**「サイト利用者全員」「ユーザー全員」はどちらも登録ユーザー全員**（ユーザーロールが土台なので、クリエイター・ギャラリーにも届く）。**「クリエイター・ギャラリー」「クリエイター」「ギャラリー」はその機能を利用中の人だけ**に絞る。どの対象でも、受け取るかどうかは③の1つの設定で決まる。

- **P90-9（メールテンプレート管理）の「自動送信」一覧（pages.js `AUTO_TRIGGERS`）も同時に直す**。本ファイルと P90-9 で発火点・カテゴリ・文面がずれないようにする（2026-09-27 に一度ずれていたのをそろえ直した）。
- 状態名・期限・ページ呼称は CLAUDE.md / transaction-states.md を参照し、**メール独自の言い換えをしない**。
- 画面（`KTN.submitDone()` モーダル・`.ktn-txn-alert` 等）とメールで、同じイベントの表現・期限値を食い違わせない。
- Drupal 実装フェーズで、共通ヘッダー/フッター部品・トークン差し込み・HTMLメール化を行う。本ファイルはその入力仕様。
