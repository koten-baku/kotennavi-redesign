# 注目のエリア（軸ページの露出）仕様

P90-17「検索・特集管理」の〈特集（軸）の設定〉タブが管理する対象の仕様。**画面の説明文はこのファイルを要約したもの**なので、画面の文言を変えるときはここも直す。実装は `KTN.axis`（`kotennavi-pages.js`）と `KTN.pages['p90-17']`。

最終更新：2026-09-20

---

## 0. この設計の狙い（検索対策）

**展覧会を探す人が検索に打ち込む言葉は「エリア」と「ジャンル」に集中する。** 検索ページ1枚ではこの言葉ごとの受け皿を作れないので、**言葉ごとに恒久URLを建てて**、検索から直接その一覧へ入ってもらう。軸ページはそのためにある。

### なぜこの組み合わせが強いのか

| | 何が効くか | 支えている仕組み |
|---|---|---|
| ① | **URLが消えない** ＝ 掲載0件になってもページは残るので、いったん付いた評価を捨てずに済む | 公開／非公開を持たない（6節） |
| ② | **孤立したページを作らない** ＝ どのURLにも必ず入口がある | 索引が全URLを毎日リンク（6節） |
| ③ | **リンクが実際にたどられる** ＝「張ってあるが誰も通らない」状態にならない | 注目枠が人の導線も配る（2〜4節） |
| ④ | **構造が日単位で安定する** ＝ クローラが来るたびに内部リンクが組み替わらない | 常設＋日付シードのローテーション（4節） |

**この4つが揃って初めて、URLの数が資産になる。** どれか1つを崩すと残りが効かなくなる＝0件のページを消せば①が、索引から外せば②が、全部を常設で固定すれば③が、ランダム表示にすれば④が崩れる。**画面の各設定は、この4つのどれかを守るために置いてある。**

---

## 1. 何を管理しているか

| 管理する | しない |
|---|---|
| 常設するエリアと**その優先順位** | 軸そのものの増減（タクソノミ側） |
| ローテーションの**しきい値** | 各ページの**枠数**（レイアウトが決める） |
| 軸ページの**導入文**（5軸すべて） | ページの**公開／非公開**（存在しない） |
| | ハブ「展覧会を探す」自身の導入文（固定文） |

**軸ページはデータから自動生成される。** 1枚ずつ作るものではなく、掲載中の展覧会データがある限りURLが存在し続ける。いま5軸・合計115URL。

---

## 2. 並びの作り方（1本の列を全ページで共有する）

```
［常設するエリア（運営が並べた順）］ → ［しきい値を超えたエリア（日付シードのハッシュ順）］
```

`KTN.axis.pick(n)` がこの列の**先頭から n 件**返す。各ページは自分の枠数だけ使う。

| 入口 | 枠数 | 枠の役割 |
|---|---|---|
| トップ | 3 | **いちばん強い入口を毎日同じ場所に置く。** いまは常設3件で埋まり、日替わりは入らない |
| 展覧会を探す | 4 | **常設に1枠だけ日替わりを足す。** 主要な入口を動かさずに、他のエリアへも順番を回す |
| 展覧会を探す ハブ | 6 | **索引が全URLを毎日リンクしている**ので、注目枠は多めに日替わりへ回せる |

枠数はいずれも**ページ側に直書き**（`pick(3)` / `pick(4)` / `pick(6)`）。`KTN.axis` は並びだけを持つ。

**入れ子になる**＝トップの3枠 ⊂ 展覧会を探すの4枠 ⊂ ハブの6枠。同じ日はどの入口から入っても同じエリアが同じ順で出る。**これが狙い**で、複数の入口から入った人の行き先がばらけないようにしている。

**枠数を設定にしない理由**＝何枠入るかはそのページのレイアウトが決める事実で、管理画面からは見えない。6枠のグリッドに8を指定すれば行が崩れる。**判断できない人に判断させる設定は置かない。**

---

## 3. 常設するエリア

- **並び順がそのまま優先順位。** 上にあるものほど枠の少ないページにも出る。
- 常設したエリアは**ローテーションの対象から外れる**（`rotatable()` が `FIXED` を除外）。同じエリアが1つの並びに二重に出ることはない。
- **常設が効くのは最大枠数（6件）まで。** 7件目以降は**どのページにも出ない**。設定には残るので、画面では該当行に「どのページにも出ません」と赤字で出し、プレビューの注記でも名指しする。**黙って効かないより、外すか順位を上げるかを運営が選べるようにする。**
- 常設の件数が、**ローテーションがどのページまで届くかを決める**。3件ならトップは常設だけで埋まり、ローテーションはトップに届かない。

| 常設の件数 | トップ3枠 | 展覧会を探す4枠 | ハブ6枠 |
|---|---|---|---|
| 0 | 3枠が日替わり | 4枠が日替わり | 6枠が日替わり |
| 3 | **効かない** | 1枠が日替わり | 3枠が日替わり |
| 6 | 効かない | 効かない | 効かない |
| 7以上 | 効かない | 効かない | 効かない＋**7件目以降はどこにも出ない** |

---

## 4. ローテーション

- 候補＝**しきい値（既定5件）以上の掲載があるエリア**から、常設を除いたもの。現在22／53エリア。
- 並びは**日付シードのハッシュ順**。同じ日は何度開いても同じで、日が替われば入れ替わる。
- しきい値を置く理由＝跳んだ先が0件だと入口自体が信用されなくなる。**しきい値未満でもURLは存在し、ハブの索引からは必ずたどれる。**

### ランダムにしない理由（この設計の根拠）

**軸ページは検索流入のために建てている。** 評価は内部リンクの張り先が安定して初めて積み上がるので、**表示のたびに張り先が変わる＝どのURLにも積み上がらない**。それでは115URLを建てた意味がなくなる。加えて、前に見たエリアを同じ場所で探せなくなる使いにくさも出る。

**日付で決まる並びなら、その2つを同時に満たせる。** 1日のあいだリンクは動かない（クローラから見て安定）。日をまたげば候補に順番が回る（露出は配れる）。

**常設を置くのは**、主要な入口だけは日によっても動かさないため。**トップに常設だけを置いているのはこの考えの最も強い形**で、いちばん評価の乗る入口からのリンク先を固定している。

**本番では並びをページ組み立て時に確定させる**（→ 7節）。クライアント側で表示後に差し替えると、クローラに内部リンクとして数えてもらえず、ここまでの設計が無意味になる。

### ハッシュ順は均等ではない（既知の性質）

30日で数えると、22候補のうち登場するのは17エリアで、最多4回・最少0回。**順番が回るのは保証されるが、回数は均等ではない。** 棚の差し込み枠は同じ問題を順送り方式へ変えて解消したが、こちらは未対応（`追174-95` の経緯と同じ論点）。

## 5. PICKS の2枠は別扱い

「展覧会を探す」の PICKS には、エリア枠とジャンル枠が1つずつある。

- **常設を含めない列から取る**ので、常設の件数に関係なく**毎日回る**。
- エリア枠は `pickArea(1, 1)`＝回転列を**1つ読み飛ばす**。同じページ下部の「エリアから探す」4枠目と同じエリアを2回出さないため。
- ジャンル枠は同じしきい値で絞ったジャンル軸（現在4／5区分。ファッションは0件で外れる）から回す。

---

## 6. 露出の調整は「注目枠への掲載」で行う

軸ページに**公開／非公開の切替はない**。同じURLを出したり消したりすると検索側の評価が落ちるため。

内部リンクは2種類あり、役割が違う。

| | 役割 | 対象 |
|---|---|---|
| **索引** | すべてのURLを検索側に見つけてもらう | ハブが全件を毎日リンク（掲載0件も外さない） |
| **注目枠** | 人の目に触れる回数を配る | 日替わりで入れ替わる |

**注目枠を持つのはエリア軸だけ。** ジャンル・行きやすさ・年間ランキング・アーカイブには運営が露出を選ぶ枠がなく、索引とタグバーからたどる。

---

## 7. 実装の単一ソース

| 値 | 置き場 | 読む側 |
|---|---|---|
| 常設リスト・しきい値 | `KTN.axis` の `FIXED` / `MIN`（`setHighlights()` で更新） | `pick()` / `rotatable()` |
| 枠数 | 各ページに直書き（P1=3／P10=4／P10-4=6） | そのページだけ |
| 画面に出すページ名と枠数 | P90-17 の `OUTLETS` 配列 | 説明文・区切り・注記・表 |
| 軸のURLの形 | P90-17 の `AXES[].url` | 「軸ページの仕組み」の表 |

**説明文の数字はすべて上の配列から組み立てる**（地の文に直書きしない）。入口や軸が増えたら配列に1行足せば、画面の説明が一斉に追従する。

**本番（Drupal）**では `FIXED` / `MIN` は設定エンティティになり、`setHighlights()` は消える。`pick()` はサーバ側で実行して初期HTMLにリンクを焼く（クライアントの乱数だとクローラに内部リンクとして拾われず、軸ページで検索資産を積むという目的が消える）。
