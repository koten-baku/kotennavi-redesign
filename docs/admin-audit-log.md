# 操作の記録（管理者の操作の監査ログ）

2026-11-01 新設（handoff 追174-376）。管理者が行った操作を、1つの記録にまとめて残すための決まり。前工程（このモック）では画面と記録する操作を決め、記録そのものは後工程（Drupal）で作る。

## なぜ残すか

- 管理者が3種類（admin・LIAISON+ 対応・編集・問合せ）いて、非公開・削除・確認は「編集・問合せ」でもできる。あとから「だれが・いつ・なぜ」を確かめられるようにする。
- 元に戻せない操作（削除・強制退会）と、お金に関わる操作（料率・キャンペーン・個別の適用）がある。間違えたときの手がかりにする。
- 利用者から「なぜ非公開になったのか」と聞かれたときに、日時と理由で答えられるようにする。
- 問題報告・削除の依頼・権利侵害への対応を、対応方針（docs/moderation-policy.md）どおりに処理したことを、あとで示せるようにする。

## 記録の決まり

- **足すだけ**。画面からは書き換え・削除ができない（admin でもできない）。サーバーが操作のたびに1行ずつ足す。
- **画面を見ただけ（閲覧）は残さない**。残すのは、内容や状態を変えた操作と、なりすましログイン。
- **なりすましログインの間の操作**は、なりすまし中の印（なりすましたユーザーの UID）を付けて同じ表に残す。
- **編集の中身（どこをどう直したか）は、コンテンツの版（Drupal のリビジョン）で持つ**。記録の表には「編集した」という1行と、主な項目の変更だけを書く（表を重くしない）。
- 残す期間は後工程で決める（目安：少なくとも3年。削除の依頼・権利侵害の対応を、あとで確かめられる長さ）。

## 1行に残す項目

| 項目 | 中身 |
|---|---|
| 日時 | 操作した日時（秒まで・サーバーの時刻） |
| 管理者 | UID と種類（A＝admin／L＝LIAISON+ 対応／E＝編集・問合せ） |
| なりすまし中 | なりすましたユーザーの UID（なりすまし中の操作のときだけ） |
| 操作 | 下の「記録する操作」の名前 |
| 対象 | 種類（展覧会・作品・記事・レビュー・コメント・クリエイター・ギャラリー・ユーザー・設定）・NID または ID・そのときの名前 |
| 理由・内容 | 削除・強制退会・非公開・個別の適用などで書いた理由／主な項目の変更前 → 変更後 |
| つながり | 対応案件の受付番号（P90-21）・お問合わせの番号など、あれば |

## 理由を書くか（2026-11-01 ユーザー確認）

「理由・内容」の列のうち、**内容（変更前 → 変更後）は自動**で入る。人が書くのは理由だけで、操作ごとに分ける。

| 理由 | 操作 | 考え方 |
|---|---|---|
| 必須 | 非公開・削除・強制退会・なりすましログイン・個別の適用・機能申込の取消・ロールの変更 | 利用者に影響が出る、または例外の操作。あとで「なぜ」を聞かれる |
| 任意 | 編集・公開に戻す | 修正依頼・報告への対応などは書けるようにしておく |
| 書かない（内容が自動） | 確認・公開・クローン・料率・キャンペーンの変更・機能申込の承認・対応案件の更新・文面・ガイド・お知らせ・特集の変更 | 何を変えたかの記録で足りる |

- **編集画面で非公開・削除をしたときは「編集」ではなく、それぞれ「非公開」「削除」の1行**。「編集」は保存ボタンで内容を保存したときだけ。直して保存してから非公開にすると2行、保存せずに非公開にすると「非公開」の1行（直した内容は保存されない）。

## 見る場所（画面）

- **P90-28 操作の記録**（admin だけ）：全件を新しい順に20件ずつ（ページ送りですべてたどれる）。操作・管理者の UID（なりすましたユーザーの UID でも）・対象の NID・ID・URL・期間で探すと、当たるものだけを20件ずつ。`?nid=` で開くと、その対象で探した状態から始まる。
- **編集画面の「このコンテンツの記録」**（P2-11・P7-11・P8-11 の「公開の状態と削除」の下・P60-21 の「編集の記録」・**admin だけ**＝2026-11-01 ユーザー指示。LIAISON+ 対応・編集・問合せの管理者には出さない）：その対象の直近5件。admin には「この〇〇の記録をすべて見る →」（〇〇＝展覧会・記事・レビュー・ガイド。2026-11-01 に「操作の記録で見る →」から改名）（P90-28 へ）。
- そのほか、今までの記録はそのまま使う：P90-5 の確認した管理者の UID、P90-21-1 の対応の記録、P90-20 の個別の適用、削除のメール DL-01A、編集画面の管理者コメント。

## 後工程（Drupal）

- 記録の表（監査ログ）を1つ作り、上の操作の API の中で1行ずつ足す（画面で足さない）。管理者の操作を記録する追加モジュール（Admin Audit Trail など）が使えるかは後工程で判断する。
- 編集はリビジョンを有効にし、記録の行から版の差へたどれるようにする。
- 記録の表は、admin も含めて画面・API から書き換え・削除できないようにする。
- モックのデータは pages.js `KTN.AUDIT`、画面は `KTN.pages['p90-28']` と common.js `ktnAdminOpsLog`。
